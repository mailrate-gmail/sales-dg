# AI 会谈辅助系统需求与设计

## 1. 文档说明

本文档为 AI 会谈辅助系统第一版需求与设计文档，用于明确系统目标、核心功能、技术路线、模块划分、数据结构与后续开发计划。

系统定位为：

> 一个运行在客户本地笔记本电脑上的 AI 会谈辅助系统，用于在客户会谈、需求沟通、销售交流等场景中实时记录语音、转换文字、识别说话人，并根据预设会晤目标生成合适的应答建议。

---

## 2. 项目背景

在客户沟通、需求调研、售前交流等场景中，沟通过程通常存在以下问题：

1. 会谈内容难以及时完整记录；
2. 需求表达口语化、碎片化，后续整理成本高；
3. 客户提出异议时，沟通人员需要快速组织专业答复；
4. 新员工缺少经验，容易遗漏关键信息或回应不当；
5. 会后纪要、行动项、客户关注点需要人工整理；
6. 涉及客户信息时，不适合将完整录音和转写内容上传到集中服务器。

因此，本系统采用本地部署方式，在客户或使用者自己的笔记本电脑上运行全部核心组件，尽量保证数据本地化，同时通过第三方大模型 API 提供智能建议能力。

---

## 3. 系统目标

### 3.1 总体目标

构建一个本地运行的 AI 会谈辅助系统，实现从语音记录、语音转文字、说话人识别、角色区分，到 AI 建议回复和会话文件保存的完整流程。

### 3.2 核心目标

1. 支持在本地浏览器页面中发起会谈记录；
2. 支持输入本次会晤目标；
3. 支持本地录音并进行语音转文字；
4. 使用本地 faster-whisper 完成语音识别；
5. 使用 SpeechBrain 完成声纹识别；
6. 使用简单能量检测方式进行语音切分；
7. 支持会前录入参会人声纹；
8. 支持在会谈过程中识别发言人；
9. 支持配置哪些参会人的发言需要 AI 生成答复建议；
10. 支持客户发言显示为白色文字，我方发言显示为黄色文字；
11. 支持根据会晤目标、历史会话和客户最新发言生成建议回复；
12. 支持完整会话记录保存和导出。

## 5. 部署模式

### 5.1 部署原则

系统采用单机本地部署模式。

每个使用者从 GitHub 拉取项目文件，在自己的笔记本电脑上运行完整系统。系统可以划分为 `server` 和 `client` 两个组件，但二者均运行在本机。

### 5.2 推荐部署方式

推荐使用 Docker Compose 部署。

示例启动方式：

```bash
git clone <repository-url>
cd ai-meeting-assistant
cp .env.example .env
docker compose up -d
```

启动后访问：

```text
http://localhost:3000
```

### 5.3 本地数据保存

系统运行过程中产生的数据保存在本地 `data/` 目录中。

```text
data/
├── participants/        # 参会人配置与声纹数据
├── sessions/            # 会话 JSON 记录
├── audio/               # 原始录音或语音片段
├── transcripts/         # 转写文本
└── exports/             # 导出的 Markdown/TXT 文件
```

## 6. 技术路线

### 6.1 前端技术

建议使用以下技术之一：

- React；
- Vue；
- Vite；
- TypeScript。

第一版建议采用：

```text
React + Vite + TypeScript
```

前端主要职责：

- 获取麦克风权限；
- 录制音频；
- 展示实时会话；
- 管理参会人；
- 配置会晤目标；
- 展示 AI 建议回复；
- 触发导出操作。

### 6.2 后端技术

建议使用：

```text
Python + FastAPI
```

后端主要职责：

- 接收前端音频；
- 进行语音切分；
- 调用 faster-whisper 转写；
- 调用 SpeechBrain 识别说话人；
- 管理参会人声纹；
- 调用第三方大模型 API；
- 保存会话记录；
- 导出文件。

### 6.3 语音识别

语音识别采用：

```text
faster-whisper
```

推荐模型：

| 使用场景 | 推荐模型 |
|---|---|
| 普通笔记本演示 | small |
| 速度优先 | base / small |
| 准确率优先 | medium |
| GPU 环境 | medium / large-v3 |

第一版建议默认使用：

```text
faster-whisper small
```

### 6.4 声纹识别

声纹识别采用：

```text
SpeechBrain
```

用途：

- 录入参会人声音样本；
- 提取参会人声纹向量；
- 对会议语音片段进行声纹匹配；
- 判断当前发言人。

### 6.5 语音切分

第一版采用简单能量检测方式进行切分。

基本思路：

1. 前端持续采集音频；
2. 后端按短时间窗口分析音频能量；
3. 当音量高于阈值时判断为有人说话；
4. 当音量持续低于阈值时判断为一句话结束；
5. 将该语音片段发送给 ASR 和声纹识别模块。

第一版不追求复杂的多人重叠语音处理，优先保证流程可用。

### 6.6 大模型调用

大模型采用第三方 API 方式，不在本地运行大模型。

系统应借鉴 OpenCode 的模型配置思路，支持多 Provider、多模型、可配置 API Key 和 Base URL。

示例配置：

```env
LLM_PROVIDER=deepseek
LLM_MODEL=deepseek-chat
LLM_API_KEY=your_api_key
LLM_BASE_URL=https://api.deepseek.com
```

后续可扩展支持：

- DeepSeek；
- OpenAI；
- 通义千问；
- 智谱；
- Moonshot；
- 其他 OpenAI Compatible API。

## 8. 核心业务流程

### 8.1 会前配置流程

```text
打开系统
  ↓
创建或选择会谈
  ↓
输入会晤目标
  ↓
维护参会人列表
  ↓
录入参会人声纹样本
  ↓
设置参会人角色和是否需要 AI 答复
  ↓
开始会谈
```

### 8.2 会中辅助流程

```text
浏览器采集语音
  ↓
后端接收音频流
  ↓
能量检测切分语音片段
  ↓
faster-whisper 转写文字
  ↓
SpeechBrain 识别发言人
  ↓
前端展示发言内容
  ↓
判断该发言人是否需要 AI 答复
  ↓
如需要，则调用大模型生成建议回复
  ↓
前端展示建议回复
```

### 8.3 会后保存流程

```text
结束会谈
  ↓
保存完整会话 JSON
  ↓
生成转写文本
  ↓
生成 Markdown/TXT 导出文件
  ↓
可选生成会议总结和待办事项
```

## 9. 功能需求

### 9.1 会晤目标管理

用户可以在会谈开始前输入本次会晤目标。

示例：

```text
了解客户当前业务流程痛点，确认是否需要进一步安排需求调研会议。
```

会晤目标用于约束 AI 建议回复的方向。

### 9.2 参会人管理

系统支持维护参会人列表。

每个参会人包含：

- 姓名；
- 角色；
- 声纹样本；
- 是否需要 AI 答复；
- 展示颜色；
- 备注。

角色建议包括：

- 我方；
- 客户；
- 其他。

### 9.3 声纹录入

用户可以为每个参会人录入声音样本。

建议录入要求：

- 每人录音 20 至 60 秒；
- 尽量在安静环境下录制；
- 使用正式会谈时相同或相近的麦克风；
- 录音内容可为任意自然讲话。

系统根据录音生成声纹向量，并保存在本地。

### 9.4 语音转文字

系统使用 faster-whisper 对语音片段进行本地转写。

转写结果包含：

- 文本内容；
- 开始时间；
- 结束时间；
- 识别语言；
- 置信度，若模型支持。

### 9.5 说话人识别

系统使用 SpeechBrain 对语音片段进行声纹识别。

识别流程：

1. 提取当前语音片段的 speaker embedding；
2. 与本地参会人声纹库进行相似度计算；
3. 选择相似度最高的参会人；
4. 如果相似度低于阈值，则标记为未知说话人；
5. 前端允许用户手动修正说话人。

### 9.6 会话展示

前端页面实时展示会话记录。

展示规则：

- 客户发言：白色文字；
- 我方发言：黄色文字；
- 未知说话人：灰色文字；
- AI 建议回复：独立区域展示。

示例：

```text
客户-李四：我们比较担心上线周期太长。

我方-张三：这个问题可以理解，我们可以分阶段推进。

AI建议：建议先共情客户对周期的担忧，再说明可通过分阶段实施降低风险。
```

### 9.7 AI 建议回复

当发言人被标记为“需要 AI 答复”时，系统调用大模型生成建议回复。

判断条件：

- 发言人角色为客户；或
- 参会人配置中 `need_reply = true`。

生成依据：

- 本次会晤目标；
- 最近若干轮会话记录；
- 客户最新发言；
- 可选的产品或业务背景信息。

### 9.8 手动修正

由于声纹识别可能存在误判，系统必须支持手动修正。

用户可以：

- 修改某条发言的说话人；
- 修改某条发言的角色；
- 重新触发 AI 建议回复；
- 标记某条发言不需要回复。

### 9.9 会话保存

系统自动保存完整会话记录。

保存内容包括：

- 会话 ID；
- 会晤目标；
- 开始时间；
- 结束时间；
- 参会人列表；
- 每条发言记录；
- AI 建议回复；
- 操作修正记录。

### 9.10 文件导出

系统支持导出会话记录。

第一版支持：

- Markdown；
- TXT；
- JSON。

后续可扩展支持：

- Word；
- PDF。

## 10. 非功能需求

### 10.1 本地化

音频采集、语音识别、声纹识别和会话存储应在本机完成。

### 10.2 隐私保护

默认情况下，原始录音不上传至第三方服务。

只有在生成 AI 建议回复时，系统会将必要的文本内容发送给配置的大模型 API。

### 10.3 可配置性

系统应支持通过配置文件调整以下内容：

- 大模型 Provider；
- API Key；
- Base URL；
- 模型名称；
- Whisper 模型大小；
- 声纹匹配阈值；
- 能量检测阈值；
- 数据保存路径。

### 10.4 可移植性

系统应支持普通笔记本电脑运行。

优先支持：

- Windows；
- macOS；
- Linux。

第一版优先保证 Linux / Windows Docker 环境可运行。

### 10.5 可用性

系统应提供简单清晰的页面，降低非技术人员使用门槛。

## 12. 大模型提示词设计

### 12.1 建议回复提示词

```text
你是我的商务会谈辅助助手。

本次会晤目标是：
{{meeting_goal}}

最近会话记录：
{{conversation_history}}

客户最新发言：
{{latest_customer_message}}
```

```text
4. 待确认问题；
5. 后续行动建议。

{{conversation_history}}
```

## 18. 风险与注意事项

### 18.1 声纹识别准确率风险

声纹识别受录音环境、麦克风距离、背景噪音、说话时长影响较大，因此必须保留人工修正功能。

### 18.2 实时性风险

faster-whisper 和 SpeechBrain 在普通 CPU 笔记本上可能存在一定延迟。第一版应优先保证可用性，而不是追求完全实时。

### 18.3 隐私风险

虽然音频和转写在本地处理，但调用第三方大模型 API 时，会发送部分会话文本。系统应明确提示用户，并支持控制发送内容范围。

### 18.4 大模型幻觉风险

AI 建议仅作为辅助，不应作为最终承诺。提示词中应约束模型不要编造产品能力、价格、交付周期等信息。

## 19. 第一版结论

本系统第一版采用以下技术路线：

```text
本地部署：Docker Compose
前端：React + Vite + TypeScript
后端：Python + FastAPI
语音识别：faster-whisper
声纹识别：SpeechBrain
语音切分：简单能量检测
大模型：第三方 API，可配置 Provider / Model / Base URL / API Key
存储：本地文件系统
```

该方案具备以下特点：

1. 适合单机本地部署；
2. 音频和声纹数据保存在本地；
3. 技术复杂度适中；
4. 适合公司 AI 技能大赛演示；
5. 后续具备扩展为正式产品的空间。
